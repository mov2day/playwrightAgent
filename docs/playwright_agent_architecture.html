PlaywrightAgent VS Code extension architecture: 12-step pipeline with 3 approval gates, showing automated, AI, and tooling stages

@PlaywrightAgent — pipeline architecture

automated
approval gate
phase 1 — setup & context ingestion
1
Repo indexer — scan, detect pattern, cache on git HEAD
Scans workspace files, detects TS/JS, identifies POM vs Screenplay via multi-signal analysis (folder names, base classes, import patterns). Caches result keyed to current git HEAD hash. On next run: HEAD diff check → skip if unchanged.
⚠ Risk: wrong pattern detection → all tests broken ⚠ Risk: monorepo with mixed patterns ⚠ Risk: cache hit on dirty working tree
Guard: require user confirmation of detected pattern before proceeding
2
Jira client — pure tooling, reads env vars, deep-links epics/tasks/subtasks
Reads JIRA_BASE_URL, JIRA_API_TOKEN, JIRA_EMAIL from env. Resolves full issue graph: epic → stories → subtasks → linked issues → Confluence pages. No AI involvement. Fails fast with actionable error if vars missing.
⚠ Risk: token in plaintext .env committed to repo ⚠ Risk: Jira rate limiting on large epics ⚠ Risk: circular issue links → infinite loop
3
Confluence client — context-optimized query, no AI key exposure
AI generates CQL query from Jira summary locally (no API call with raw key). Tooling executes query. Returns content ranked by relevance score. CONFLUENCE_BASE_URL, CONFLUENCE_API_TOKEN from env only.
⚠ Risk: CQL too broad → 50 irrelevant pages ⚠ Risk: Confluence behind SSO, not API-accessible
phase 2 — context fusion & confidence scoring
4
Context analyzer — score confluence relevance, chunk for context window
Computes confidence score (0–1) from: Jira detail richness + Confluence hit quality + acceptance criteria presence + linked test cases. User-provided context always gets weight=1.0 (highest priority, overrides plan-level details).
Confidence thresholds
≥ 0.75 — proceed to plan generation
0.40–0.74 — show score, ask user how to proceed
< 0.40 — hard stop, never generate placeholder tests
⚠ Risk: score threshold gaming — user context inflates score artificially ⚠ Risk: context window overflow — Jira+Confluence+Repo exceeds 200k tokens
GATE 0 — low confidence hard stop
phase 3 — plan generation
5
Skills loader + plan generator — repo patterns + context → test plan
Loads skills from .playwright-agent/skills/ (page objects, fixtures, helpers, naming conventions, assertion patterns). Feeds skills + repo examples + fused context to AI. Output: structured plan JSON — each test has: name, description, acceptance criteria covered, risk level, estimated LOC, page objects required.
⚠ Risk: AI invents page objects that don't exist in repo ⚠ Risk: duplicate tests for scenarios already in repo
Guard: plan references only existing repo symbols — validated against repo index before display
GATE 1 — user approves/rejects individual tests in plan
phase 4 — test generation
6
Test generator — strictly pattern-bound, few-shot from repo, tsc-validated
For each approved test: extract 2–3 real repo examples as few-shot anchors. Constrained system prompt: "generate ONLY using these imports, ONLY these page object methods, ONLY these fixture patterns." Post-generation: run tsc --noEmit on generated file. If type errors → re-attempt once → if still failing → surface to user, never silently continue.
⚠ Risk: tsc passes but test logic is wrong (type-correct hallucination) ⚠ Risk: imports from non-existent paths ⚠ Risk: AI uses deprecated page object methods
GATE 2 — user reviews generated test preview in chat
phase 5 — file write, execution & summary
7
File writer — diff-patch existing files, never overwrite blindly
New file → create at computed path following repo conventions. Existing file → generate diff, apply via WorkspaceEdit, show unified diff to user before applying. Conflict on same test name → error, ask user to rename. All writes are reversible via VS Code undo stack.
⚠ Risk: path collision with existing test ⚠ Risk: adding imports that break existing file's barrel exports
8
Test runner — local playwright execution, HTML report, summary
Runs only the newly written test files (filtered by path). Uses repo's own playwright.config.ts. Streams stdout to VS Code output channel. On completion: generates HTML report, opens in webview, posts summary to chat (pass/fail count, flaky indicators, duration).
⚠ Risk: tests need running app/env — fail with misleading errors ⚠ Risk: playwright not installed / version mismatch ⚠ Risk: test runner hangs — no timeout kills it
Core invariants — never violated
🔒 API keys never passed to AI — tooling only uses env vars directly
🔒 No test generated below confidence threshold — hard stop, not warning
🔒 All 3 approval gates are blocking — webview crash = pipeline halt, not bypass
🔒 Generated code validated by tsc --noEmit before user preview
🔒 AI anchored to real repo examples as few-shot — no open-ended generation
🔒 Existing file edits go through diff-patch — old code never silently clobbered
